# 工作区统一规范（Codex / DSH / Antigravity 通用）

## 一、称呼与身份
- 用简体中文回答；仅代码标识符、命令、日志、报错保持原文。

## 二、命名规范（强制）
1. **项目目录**：新建宿主工程目录默认用中文名称（如 `智能限频工具`），不用英文项目名。
2. **会话目录**：`<工作区>/会话/YYYY-MM-DD-HHMM-<中文短主题>`；有宿主会话脚本时以宿主为准。
3. **内容命名**：固定双核心文件 `会话说明.md`、`归档索引.md`；跨 AI 交接用 `交接说明.md`；
   子目录默认 `证据`、`备份`、`脚本`、`截图`（历史 `evidence` 兼容保留）。
4. **项目文档**：优先中文命名（`项目说明.md`、`规格说明.md`、`施工日志.md`）。

## 三、会话工作区协议（强制）
1. **一个对话 = 一个目录**：写任何文件之前先在 `会话/` 下确定本对话目录，后续轮次固定复用。
2. **身份元数据**：目录根写 `.session.json`：
   ```json
   { "provider": "dsh", "thread_id": "<DSH_SESSION_ID>", "topic": "<主题>", "created_at": "<ISO8601>" }
   ```
   `thread_id` 一经写入不得改动；`topic` 仅用于展示，**不参与任何匹配**。
3. **同名不同对话**分属两个目录，不共用、不读对方目录里的记忆文件。
4. **过程文件不外溢**：md、草稿、分析、证据、一次性脚本、dump、截图只进本会话目录或其子目录；
   不得散落在工作区根、`项目文档`、其他会话目录。
5. **工程与过程分离**：宿主工程源码、构建产物、正式文档放 `<工作区>/<中文宿主工程目录>/`，
   会话目录只留过程记录与证据，用绝对路径指向外部产物。
6. **结论升格**：长期有效的结论写进宿主工程的现状文档，会话目录只留审计轨迹。
7. **只清理本轮中间产物，永不删除会话目录。**

## 四、任务执行规则
- 先执行，后总结；不用解释或免责代替动作。
- 缺信息用占位符继续推进并标注，不用提问卡住任务。
- 修改既有文件前先读取；配置/系统改动先备份并记录 SHA-256。
- 不主动 `git commit` / `git push`，除非明确要求。

## 五、记录与汇报
每轮结束前：更新 `会话说明.md` → 追加 `归档索引.md` → 汇报 **做了什么 / 结论 / 证据路径 / 未验证项**。
事实与推测分开写。

## 六、目录示例
```text
<工作区>/
├─ AGENTS.md
├─ 会话/
│  └─ 2026-11-15-0145-示例任务/
│     ├─ .session.json
│     ├─ 会话说明.md
│     ├─ 归档索引.md
│     ├─ <一次性脚本>
│     └─ 证据/
│        └─ 备份/
└─ <中文宿主工程目录>/
```

## 七、删除会话前
`.session.json` 缺失或不含 `provider=dsh` / 真实 `thread_id` 的目录，`dsh-session-delete` 一律保留。
删除前用 `cat 会话/<目录>/.session.json` 核对归属。
